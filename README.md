# SCAMSHIELD AI  ·  *Detect. Explain. Protect.*

**Team:** Safeguard  |  **Event:** CRYPTAURA 2.0  |  **Problem Statement ID:** AURA-7.1 - *Detecting AI-Generated Scams & Phishing*  |  **Theme:** AI/ML for Cybersecurity

## Problem
Scam and phishing messages are now polished, multilingual/code-mixed and mass-produced. Basic detectors only output "scam", which users cannot verify or learn from.

## Solution & key innovation
A **hybrid, explainable** detector: ML classifier + security rule engine + offline URL analyzer + weak AI-generated-content signal, combined into a transparent risk assessment. It tells the user **what** it thinks (potential category), **why** (highlighted evidence cards), **how risky the link is**, and **what to verify** - and says **"Uncertain"** when signals conflict.

## Features
Text/SMS/email/social/URL input · 10 scam categories + legitimate + unknown (configurable in `app/config/categories.json`) · structured evidence with highlighting · URL feature analysis (never opened) · English + Tamil-English handling · AI-generated/scaled content *indicators* · evaluation page · session analytics · privacy and responsible-AI page.
Screenshot OCR is **not implemented** (upload is validated and clearly labelled as a disabled extension).

## Architecture
`Input → Validation → Language detection → Preprocessing → TF-IDF + LogReg | Rule engine | URL analyzer → Hybrid risk engine → Evidence → Explanation → Streamlit dashboard`

```
app/config     settings + categories.json      app/rules      indicator engine
app/services   analyzer, url_analyzer, risk_engine, ai_content
app/frontend   streamlit_app.py                app/utils      upload validation
ml/            preprocess, cores, build_dataset, train, predict, evaluate
tests/         28 unit tests                   docs/          test report, demos, pitch, PPT
```

## AI/ML approach
TF-IDF (word 1-2 grams + char 2-5 grams) → Logistic Regression (multi-class). Linear SVM and Complement NB are compared on validation. Vectorizer fit on **train only**. Rule/URL/ML signals are combined with hand-set weights (`app/config/settings.py`), **not tuned on data**.

## Dataset (read this)
**100% synthetic.** 948 rows generated from hand-written templates and composed clauses (`ml/build_dataset.py`, `ml/cores.py`). No real messages, OTPs or personal data. Splits are made per template/clause, so test wording is never seen in training. **No public dataset is bundled**; add one (e.g. public SMS-spam / phishing corpora) under `data/raw/` for a real-world evaluation.

## Evaluation (generated by `python -m ml.train`; synthetic test set, n=204)
| Metric | Value |
|---|---|
| Test macro-F1 (multi-class) | 0.812 |
| Scam precision / recall (binary) | 1.0 / 0.9262 |
| False positives (legit flagged) | 0 |
| False negatives (scam missed) | 11 |
| Tamil-English subset (n=42) accuracy / scam recall | 0.4762 / 0.9333 |

These numbers describe the **synthetic** test set only. A separate check on 12 hand-written unseen messages scored **7/12 before** and **9/12 after** a regex bug fix (see `docs/robustness_*.txt`); the 12 are now development cases, so 9/12 is not an unbiased estimate. Expect real-world performance to be lower.

## Install & run
```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m ml.build_dataset      # creates data/processed/scam_dataset.csv
python -m ml.train              # saves ml/artifacts/* and metrics.json
python -m ml.evaluate           # prints metrics
python -m unittest discover -s tests -v    # or: pytest -v
streamlit run app/frontend/streamlit_app.py
```

## Privacy & security
Text is analysed in memory; the app writes nothing to disk and does not log submissions. Input length limit, control-character stripping, HTML-escaped rendering, upload type/size checks, no secrets in code (`.env.example`), URLs never fetched. Hosting platforms may add their own logs.

## Limitations (honest)
- Synthetic training data → weak generalisation to novel scam styles (e.g. "hi mom, new number" scams are often missed).
- Tamil-English **category** accuracy on unseen wording is low (0.4762); scam-vs-legit detection is better. Only English and Tamil-English were tested.
- URL brand check uses a tiny demo list; no live reputation/WHOIS lookups.
- AI-generated-content analysis is a weak heuristic and cannot prove authorship.
- No OCR, no CORS/API server or rate limiting (Streamlit only), UI not load-tested.
